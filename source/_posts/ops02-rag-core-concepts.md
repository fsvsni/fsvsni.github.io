> 对应课件：第 2 讲 RAG 核心概念深入
> 本篇目标：从**设备运维**视角理解 Embedding、向量检索、混合检索、Reranker 这些核心概念——它们如何解决运维知识"散、杂、急"的问题。

## 一、运维知识的三大痛点

设备运维知识有三个特点，决定了检索方式：

| 痛点 | 例子 | 对检索的要求 |
|---|---|---|
| **散** | 告警 SOP 分散在多份文档 | 需要语义聚合 |
| **杂** | 巡检表、维修手册、工单规则混合 | 需要按 source 过滤 |
| **急** | 告警发生要立刻查处理步骤 | 需要快、要准 |

## 二、Embedding：让运维知识可语义匹配

### 2.1 一句话理解

**Embedding（嵌入）** 把文本变成向量，语义相近的文本向量也相近。设备运维中：

```
"日检异常怎么升级"  → 向量A
"巡检发现异常如何上报" → 向量B
向量A 与 向量B 余弦相似度 ≈ 0.92（语义相近）

"配件更换流程"     → 向量C
向量A 与 向量C 余弦相似度 ≈ 0.35（语义无关）
```

> 巡检员用自己的话提问，系统用语义理解匹配告警 SOP——这就是 RAG 的价值。

### 2.2 设备运维中的典型语义匹配

| 员工提问 | 能匹配到的资料（字面不同） |
|---|---|
| "泵机声音不对咋办" | 维修手册中"异常噪音排查"章节 |
| "日检发现漏油" | 巡检标准中"泄漏检查项" |
| "这个告警要不要上报" | 告警 SOP 中"告警分级与升级" |

## 三、Dense 检索：理解语义

Dense 检索用稠密向量找语义相近的片段：

```
"设备过热" → 能匹配到"温度超限""过热保护"（语义相关）
```

**适合**：巡检员提问方式多样，需要理解改写、同义词。

## 四、Sparse 检索（BM25）：精确匹配术语

Sparse 检索用关键词（BM25）精确匹配：

```
"工单 W0001" → 精确匹配含该工单号的内容
"故障码 E-203" → 精确匹配含该故障码的内容
```

**适合**：设备运维有大量精确术语（故障码、设备型号、工单号），BM25 保证精确命中。

## 五、混合检索：运维场景为什么必须混合

运维问题**既有语义又有术语**：

| 问题 | 需要 Dense | 需要 Sparse |
|---|---|---|
| "泵机异常怎么处理" | ✅ 语义 | |
| "故障码 E-203 什么意思" | | ✅ 精确 |
| "日检异常怎么升级" | ✅ 语义 | ✅ "日检""升级" |

> 只用 Dense：故障码 E-203 可能召回不到精确文档；只用 Sparse："泵机异常"可能漏掉语义相近的"振动过大"。混合检索两者兼顾。

## 六、Reranker：从召回到精排

混合检索召回 Top-30，需要**精排**。设备运维中，精排尤为重要：

- 召回的一堆文档里，可能只有 1-2 个是**真正匹配当前故障**的
- 排序错误 = 巡检员看了无关文档 = 处理延误

BGE Reranker（CrossEncoder）对"问题+文档"联合打分，把真正相关的排到前面。

## 七、设备运维的完整检索链路

```
巡检员："日检异常怎么升级"
  → 意图识别（告警/升级类）
  → 检索计划（inspection + alarm source）
  → 查询向量化（BGE-M3）
  → 混合检索（Dense 语义 + BM25 关键词，过滤 source）
  → Reranker 精排
  → 上下文构建
  → LLM 给出升级步骤（流式）
```

## 八、重点掌握

1. **Embedding**：文本 → 向量，语义相近则向量相近
2. **Dense**：语义匹配，适合多样化提问
3. **Sparse（BM25）**：精确匹配故障码/设备型号/工单号
4. **Hybrid**：两者结合，运维场景标配
5. **Reranker**：从召回中精排，保证"看对文档"
